# Step 6 — Kafka Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A tagged scenario is recorded and shown across a Kafka hop: orders-service publishes `order-placed`, a new
shipping-service consumes it, and the board and sequence view show producer → topic → consumer with the async gap.

**Architecture:** The sandbox gains a broker and a consumer service. The agent extension adds the message value and
headers to the OTel agent's own producer and `process` spans; the reporter maps those spans to two new events
(`kafka.produce`, `kafka.consume`); the viewer turns them into steps to and from a topic component, the consume a root
step linked to its produce by `causedBy`.

**Tech Stack:** Kotlin, Spring Boot 4.1.2, Spring Kafka (managed by Boot), Kafka clients, OTel Java agent 2.33.1
(extension: Java, ByteBuddy advice), Testcontainers 2.0.5, React + TypeScript (Vitest, Playwright).

**Spec:** `docs/superpowers/specs/2026-11-03-step-6-kafka-design.md`

## Global Constraints

- Branch `step-6-kafka`. macOS only; no CI. Never merge to master before the owner has run the stack and the viewer and
  said OK.
- Broker image `apache/kafka:4.1.0` everywhere (compose and Testcontainers); KRaft single node; no ZooKeeper.
- Topic `order-placed`, 1 partition, replication 1; consumer group `shipping`; record key = order id.
- Ports on `127.0.0.1` only: Kafka `9092` (host listener), shipping-service `8082`, shipping-db `15434`.
- Schema version 5; versions 1–4 still deserialise. Event type names `kafka.produce`, `kafka.consume`.
- Component id of a topic: `ComponentIds.topic(name) = "topic-" + slug(name)`; component type `"topic"`; connection
  kind and step kind `"kafka"`.
- Span attributes: `stack.kafka.value`, `stack.kafka.value_truncated`, `stack.kafka.headers` (JSON object of header
  name, case kept, to list of values).
- Values: `String` as is; `byte[]` / `ByteBuffer` as `<n bytes>`; null → no attribute; anything else through
  `BoundedValueSerializer`; cut to `StackAttributes.MAX_BODY_CHARS`. Header values: UTF-8 when valid, else `<n bytes>`.
- Agent hooks never throw into the application (`suppress = Throwable.class` and a catch-all in helpers).
- Every commit ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **A consume whose produce is not in the run** (produced untagged, or in another run): it must still be a root step
   with `causedBy = null`, no gap note, and "produced by" absent rather than wrong. Pinned in Task 6 and Task 8.
2. **A record with a null value (tombstone) or a binary header** (e.g. a header written by another library): no
   `stack.kafka.value`, and the header shows `<n bytes>`, never mojibake or an exception. Pinned in Task 3.
3. **A send that fails** (no ack: partition and offset absent, `error.type` set): the reporter keeps the event with
   null partition/offset, and the viewer marks the produce step failed. Pinned in Task 5 and Task 7.
4. **A curated (accepted) Kafka connection** read from the workspace with no run on disk: the topic end is typed
   `topic`, not `service`, and keeps its topic display name. Pinned in Task 6.
5. **A recording made before step 6** (schema 4) and the existing fixtures: flows and sequence layouts unchanged
   (no `causedBy`, response rows as before). Pinned by the existing suites staying green in Tasks 4, 6 and 8.
