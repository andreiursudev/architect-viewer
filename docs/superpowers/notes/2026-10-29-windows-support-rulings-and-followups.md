# Windows support — rulings and deferred follow-ups

Decisions the agent made on the owner's behalf while making the tool and the sandbox run on Windows (D26 lifted, see
the spec's revision note), and follow-ups deliberately left open. Commits `91d2ce1`, `becdee2` (board layout only) and
`2b61ff9` on master. Machine: Windows 11, Podman instead of Docker Desktop (no Docker Desktop licence on this PC).

## Rulings

- Ruling W1: `.gitattributes` checks every text file out with LF (`* text=auto eol=lf`), CRLF only for `.bat`/`.cmd`, and the working tree was renormalised — why: with `core.autocrlf=true` the checkout had CRLF, which breaks `gradlew` and the sh launcher in Git Bash and the byte-for-byte golden/snapshot tests — cost if wrong: Windows editors see LF files (harmless).
- Ruling W2: the Gradle builds provision Java 25 themselves: foojay toolchain resolver (`1.0.0`, literal in `tool/`, `tool/build-logic/` and `sandbox/` settings) and `tool/gradle/gradle-daemon-jvm.properties` (`toolchainVersion=25`) — why: the owner's default Java is 21 and must stay so; `build-logic` is compiled to Java 25 bytecode, so the daemon itself needs 25 — cost if wrong: a first build downloads a JDK into `~/.gradle/jdks`. The properties file was generated with `updateDaemonJvm` in `sandbox/` and moved to `tool/gradle/`, because `tool/` cannot even configure on Java 21; `sandbox/` keeps no daemon criteria (its plugins run on 21).
- Ruling W3: Windows launcher `stack-viewer.cmd` next to the sh one, same behaviour (Java 25 check, `Picked up` line skipped, jar next to the script via `%~dp0`). It takes only a real `java.exe` from a home variable, so the tests fake Java on Windows with a `java.cmd` first on `PATH` (home variables removed); the CDPATH test stays POSIX-only — cost if wrong: the version check against a fake older Java is only exercised through `PATH` on Windows.
- Ruling W4: both launchers take Java from `STACK_VIEWER_JAVA_HOME`, else `JAVA_HOME`, else `PATH`; error messages name the variable used — why: the owner keeps Java 21 in `JAVA_HOME`/`PATH` for work projects and points only the viewer at Java 25 (a user environment variable) — cost if wrong: one more variable to document. `LauncherScriptTest` removes `STACK_VIEWER_JAVA_HOME` unless a test sets it, so a developer's own setting cannot steer the fakes.
- Ruling W5: the launcher's "starts the viewer" test sets `JAVA_HOME` to the test JVM's `java.home` instead of using whatever Java the machine has — why: deterministic on any machine (here the default is 21) — cost if wrong: none.
- Ruling W6: `.cmd` messages that print a path stay out of `( )` blocks — why: a `)` in a path (`Program Files (x86)`) would end the block; a test uses a folder name with parentheses — cost if wrong: none.
- Ruling W7: Playwright starts the viewer with the toolchain's Java (`e2eTest` passes `STACK_VIEWER_JAVA`, from the `jvm-toolchains` plugin) else `java`, and quotes paths with plain double quotes instead of `JSON.stringify` (which doubled Windows backslashes) — cost if wrong: none.
- Ruling W8: `.gitignore` re-includes `/tool/viewer-backend/src/dist/` — why: the root `dist/` rule silently ignored the new `.cmd` (the sh launcher was tracked only because it had been force-added) — cost if wrong: none.
- Ruling W9: README commands run unchanged in PowerShell: `docker compose -f sandbox/docker-compose.yml …` replaces `(cd sandbox && …)` (Windows PowerShell 5.1 has no `&&`), and the curl recording-window example gets an `Invoke-RestMethod` twin; `tool/gradlew` resolves to `gradlew.bat` in PowerShell — cost if wrong: none.
- Ruling W10: `:reporter:dockerImage` builds with `--load` — why: with a buildx builder on the `docker-container` driver (this machine) the image stayed in the build cache and Compose (`pull_policy: never`) could not find it — cost if wrong: none.
- Ruling W11: Podman support is an override file, `sandbox/docker-compose.podman.yml` (`start_interval: !reset null`, `interval: 10s` for both services), not a change to the base file — why: Compose refuses `healthcheck.start_interval` on Podman's API, and on Docker `start_interval` keeps health probes (traced, they land in `_unassigned`) rare after startup — cost if wrong: on Podman a probe every 10s.
- Ruling W12: on Podman, Compose builds with the classic builder (`DOCKER_BUILDKIT=0`, `COMPOSE_BAKE=false`), documented in README "With Podman" — why: BuildKit in a separate builder container streaming two images into Podman at once hung Podman's Docker-compatible API (`docker ps` hung while `podman ps` answered; fixed by `podman machine stop/start`, with the owner's OK) — cost if wrong: none; the classic builder is Podman's own buildah and was faster.
- Ruling W13: `sandbox/recordings/.gitkeep` is committed (both `.gitignore`s re-include it) — why: Podman, unlike Docker Desktop, does not create a missing bind-mount source — cost if wrong: none; the viewer and the acceptance test only read subfolders.
- Ruling W14: the acceptance test detects Podman (engine version component "Podman Engine") and then adds the override and the classic-builder environment, skips Testcontainers' ambassador (it needs container links: `link is not supported`), and waits from the host on the published ports (reporter `/api/recordings/active`, both `/actuator/health`) before seeding — why: on this machine Podman forwards published ports some 20s after the containers are up and healthy, and the first request was cut (`An established connection was aborted`); the Docker path is unchanged because it could not be re-run here — cost if wrong: two code paths in one test.

## Deferred follow-ups

- Not re-run on macOS after these changes: the sh launcher tests (only smoke-tested by hand in Git Bash, incl. the new `STACK_VIEWER_JAVA_HOME` precedence) and the acceptance test's Docker path (code unchanged).
- On Windows the viewer writes machine files (`boards/*.layout.json`, notes) with CRLF (system line separator in the pretty printer); git normalises them, but byte-identical output across OSes would need an explicit `\n`.
- `gradle-daemon-jvm.properties` pins foojay download ids for Java 25; regenerate with `updateDaemonJvm --jvm-version=<n>` when the Java version changes. The foojay plugin version is a literal in three settings files, outside the version catalog.
- Podman port-forwarding lag also hits manual use: a request right after `up --wait` can be cut (README troubleshooting entry only).
- The manual recording-window example (README) produced its run folder on Windows, but its events were not verified: the check script took the stack down within a second, before the batch export.
- `.cmd` launcher: paths containing `&` or `%` in `STACK_VIEWER_JAVA_HOME`/`JAVA_HOME` or the install folder are not handled in the error messages (untested).
- Naming: `STACK_VIEWER_JAVA` (Playwright, a java executable) and `STACK_VIEWER_JAVA_HOME` (launchers, a JDK home) are close; unify if a third use appears.

## Environment notes

- Java: default Java 21 (`JAVA_HOME` user variable, `PATH`); Temurin 25 installed without `PATH`/`JAVA_HOME` (`winget install EclipseAdoptium.Temurin.25.JDK --override "/quiet ADDLOCAL=FeatureMain"`) at `C:\Program Files\Eclipse Adoptium\jdk-25.0.5.8-hotspot`, referenced by the user variable `STACK_VIEWER_JAVA_HOME`. Gradle's own JDK 25 is in `~/.gradle/jdks`. A new user variable reaches only processes started afterwards (terminal tabs of an app started earlier do not see it).
- Containers: no Docker Desktop (installed 2026-01-12, uninstalled 2026-01-14; log folders `%LOCALAPPDATA%\Docker` and `C:\ProgramData\DockerDesktop` remain). The `docker` CLI comes from Rancher Desktop 1.22.0; the engine is the Podman 5.7.1 machine (WSL), which serves the Docker API on `npipe:////./pipe/docker_engine`. The default buildx builder uses the `docker-container` driver. A gcloud credential helper for a private registry prints auth warnings during builds; harmless.
- Agent environment: the agent's own shell cannot open loopback sockets for Java ("Unable to establish loopback connection" from the Gradle daemon, even unsandboxed), so Gradle builds and the sandbox runs went through the app's terminal tabs.
